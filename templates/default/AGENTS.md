# AGENTS

本文件适用于所有项目和代码仓库，作为编码的全局偏好和指南。

仓库内的 AGENTS.md、SKILLs、现有代码风格优先级更高；如果发生冲突，以更靠近当前工作目录的项目规则为准！

## 工作原则

- 直接表达，当方案不够好时主动指出并给出替代方案
- 只解决用户明确要求的问题，不要为了显得主动、专业或“顺手优化”，把任务范围扩展到无关内容
- 优先保持现有架构、命名、目录组织、代码风格和测试习惯

## 代码修改偏好

- 避免出现巨型文件，绝大部分情况单文件代码行数应低于 500 行，如果更改导致代码行数超出，应主动寻求拆分，但部分情况不适用:
  - 自动生成的文件。例如：类型声明、protobuf 输出、SDK 代码
  - 数据文件。例如：地区数据、SQL 种子文件、配置文件
  - 构建用于生产环境的文件
- 避免引入 fallback/兜底逻辑，重构时彻底替换旧实现
- 优先小 diff、局部修改、清晰边界
- 不要引入不必要的抽象、框架、状态管理或设计模式
- 公共 API、复杂逻辑、非显然权衡需要适量注释

## 依赖与技术选型

- 不要擅自添加新的生产依赖
- 优先使用项目已有技术栈
- 从零开始的项目或者就项目添加新的依赖，应始终使用它们的最新版本，禁止凭借模型权重来决定最新版本是什么，必须要联网确定
- 优先查阅官方文档、release notes、changelog、源码仓库

## 效率

- 遇到重复性错误模式，主动将经验写回本文件

# 语言与沟通风格

- 默认用中文沟通，技术术语保留英文原文
- 注释使用中文编写
- 避免废话文学、吹捧用户，保持务实、专注、直接
