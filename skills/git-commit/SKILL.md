# Git 提交

根据项目待提交的代码编写高质量的 Git 提交信息，并为用户执行 Git 提交操作，且推送至远端仓库。


## 提交格式

```
<类型>(<范围>)!: <描述>

[可选的正文]

[可选的脚注]
```

脚注可以包含关联的 issue 编号、破坏性变更提示等元信息。破坏性变更提示应该以 `破坏性变更:` 开头，并提供详细说明。

## 提交类型

| 类型       | 说明                        |
| ---------- | ------------------------------ |
| `feat`     | 新功能                        |
| `fix`      | Bug 修复                        |
| `docs`     | 仅文档修改             |
| `style`    | 格式/样式 (无逻辑)    |
| `refactor` | 代码重构 (无功能/修复) |
| `perf`     | 性能改进        |
| `test`     | 测试相关              |
| `build`    | 构建相关     |
| `ci`       | 持续集成              |
| `chore`    | 日常维护，杂项             |
| `revert`   | 撤销提交                  |



## 步骤

1. **分析变更**：首先分析待提交的代码变更，确定哪些文件被修改、添加或删除，以及这些变更的目的和影响。
2. **编写提交信息**：根据分析结果，参考*提交格式*编写清晰、简洁且有意义的 Git 提交信息。
3. **执行提交**：使用 Git 命令行工具执行提交操作，将变更提交到本地仓库。
4. **推送到远端**：将本地提交推送到远端仓库，以便其他团队成员可以看到最新的变更。

## 约束

- **提交信息必须使用中文**。
