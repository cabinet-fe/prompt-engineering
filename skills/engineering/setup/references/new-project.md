# 新项目：反向提问

用 <@交互式提问> 分批问，等用户答完再问下一批。已从 README / 用户消息里知道的不要再问。

## 第 1 批：产品

1. 做什么？一句话。
2. 主要用户是谁？
3. 是否已经定了技术栈？若已定，让用户直接列出。

## 第 2 批：技术栈（第 1 批未定时才问）

按适用性提问，不要把 Web 全家桶甩给 CLI 项目：

- 语言 / runtime / 包管理器
- 框架
- 数据存储
- 是否分前后端、是否 monorepo
- 测试工具
- 部署方式

## 第 3 批：规范

只问代码里看不出来、必须人定的：

- 命名：已有团队习惯，还是跟语言惯例
- 注释语言
- 测试：什么必须写
- 接口风格（若有 API）
- 明确不想要的做法

## 写入规则

- 回答写入对应 docs，不要堆进 `AGENTS.md`
- 用户说「先按惯例」：选该语言/框架的主流惯例，在 `DEV-STANDARDS.md` 写明「采用 X 惯例」，不要编造独特规范
- 用户拒绝回答的章节：不写进 docs，列入 `ARCHITECTURE.md` 的「未决」
