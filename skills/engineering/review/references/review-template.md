# 评审产出模板

只使用这些标题。「结论」必须与阻塞项一致：阻塞项非「无」则不通过。坏味道只进 Standards，不进阻塞项。

## 阶段：`.agents/cooking/<feature>/reviews/Pn.md`

```markdown
# P<n> 评审

## Spec

- 通过 / 不通过
- <证据：哪条完成标准满足或缺失；是否超出范围>
- cooking `spec.md` 的「影响文件」能否 parse；新增/删除/修改是否覆盖本阶段实际改动

## Standards

- 通过 / 不通过
- 文档：<哪条规范；代码类触及 CODE-MAP 1～6 时对应行是否已改；已有技能 / 包内 AGENTS.md / ACCEPTANCE.md 是否被说错>
- 技能：无对应 / <技能名：遵守或违反哪条>
- 坏味道：无 / <名称与位置；启发式，不阻塞>

## 阻塞项

- 无
- 或：必须修完才能通过的条目

## 建议

- 无
- 或不阻塞的改进

## 结论

- 通过 | 不通过

## 评审记录

- 无
```

「结论」与 `Pn.md` 的「评审」必须一致。每次阶段评审不通过时把本次阻塞项追加进「评审记录」；再次评审不得擦掉既有记录。阶段评审始终写入同一份 `reviews/Pn.md`，不拆成多份。git 节仍只用于对话产出，不落 `reviews/`。

## git：只写在对话里

```markdown
## 对照
- 范围：<实际使用的 git diff 命令>
- 提交：<oneline 列表，或「工作区未提交」>

## Standards
- 通过 / 不通过
- 文档：<哪条规范；代码类触及 CODE-MAP 1～6 时对应行是否已改；已有技能 / 包内 AGENTS.md / ACCEPTANCE.md 是否被说错>
- 技能：无对应 / <技能名：遵守或违反哪条>
- 坏味道：无 / <名称与位置；启发式，不阻塞>

## 正确性
- 通过 / 不通过
- <证据>

## 阻塞项
- 无 / 必须修的条目

## 建议
- 无 / 不阻塞的改进

## 结论
- 通过 | 不通过
```
