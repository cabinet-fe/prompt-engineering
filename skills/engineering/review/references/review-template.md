# 评审产出模板

只使用这些标题。「结论」必须与阻塞项一致：阻塞项非「无」则不通过。坏味道只进 Standards，不进阻塞项。

## 阶段：`.agents/cooking/<feature>/reviews/Pn.md`

```markdown
# P<n> 评审

## Spec

- 通过 / 不通过
- <证据：哪条完成标准满足或缺失；是否超出范围>

## Standards

- 通过 / 不通过
- 文档：<哪条规范；代码类触及 CODE-MAP 1～6 时对应行是否已改>
- 技能：无对应 / <技能名：遵守或违反哪条>
- 坏味道：无 / <名称与位置；启发式，不阻塞>

## 规格影响

- 无命中 / 命中条目：是否破坏已归档能力（对照未 sync 的条目；范围内演进不阻塞，记通过后需 sync）
- cooking `spec.md` 的「影响文件」能否 parse；新增/删除/修改是否覆盖本阶段实际改动

## 阻塞项

- 无
- 或：必须修完才能通过的条目

## 建议

- 无
- 或不阻塞的改进

## 结论

- 通过 | 不通过
```

「结论」与 `Pn.md` 的「评审」必须一致。

## git：只写在对话里

```markdown
- 提交：<oneline 列表，或「工作区未提交」>

- 文档：<哪条规范；代码类触及 CODE-MAP 1～6 时对应行是否已改>

- 坏味道：无 / <名称与位置；启发式，不阻塞>

## 正确性
- 通过 / 不通过
- <证据>

## 规格影响
- 无命中 / 命中条目：是否破坏已归档能力（对照未 sync 的条目；范围内演进不阻塞，记通过后需 sync）

## 阻塞项

## 建议

## 结论
- 通过 | 不通过
```
