# analysis

用户点名本技能并抛出问题后，按固定打法给出结论与建议。不要因提到「分析」等词自动进入。禁止啰嗦和故作高深。

代码改动评审归 `review`，需求收敛归 `explore`。本技能不做这两件事；用户要的是其中之一则停止并指向对应技能。

## 统一工具定义

- `交互式提问`：Agent 内置的向用户提问并给出选项的工具，各 Agent 命名不同（如 `AskUserQuestion`、`AskQuestion`）。本技能所有向用户的提问都用它。

## 只读

禁止改代码。除用户确认落盘的那份报告外，禁止改任何文件。子代理同样只读。

没有要分析的问题：停止，让用户给出问题。

## 产出形式

用户调用时已指定则照做。未指定则用 `交互式提问` 在「对话内结论」与「落盘 markdown 报告」中二选一；未确认前不交付。

选择落盘：由用户给出路径（允许自定义输入）；没有路径则不写文件。技能只写该报告文件，不改其它路径。

两种形式都按 [summary-template.md](references/summary-template.md) 交付，正文相同。

## 工作流

写死为这三步，不要换成别的打法：

1. **拆维度**：按当前问题拆成若干分析维度。维度随问题而定，不要套固定类型。
2. **并行派多个子代理分头分析**：每个维度一个子代理，并行启动。任务书写明：只分析该维度、只读、不要改任何文件；返回该维度的事实与判断，不要按模板写全文。没有子代理工具：停止，不在主对话降级代做各维度。
3. **按模板汇总**：子代理返回后，按 [summary-template.md](references/summary-template.md) 汇总。章节固定且仅此五章：背景 / 方法 / 发现 / 结论 / 建议。所有分析共用这一套，不得按问题类型换模板或加分支章节。

然后按已确认的产出形式交付。
