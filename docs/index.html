不止是技能包：一套真正的提示词工程

工作流管住从需求到交付的过程，技能库对齐语言框架的真实写法，文档库引擎让内部库文档跟得上代码、能被 AI 直接检索。

这个仓库分三块。工作流：从需求梳理到交付归档的标准管线，治临时记录乱堆、过程不可控。技能库：25 个即装即用的 Agent 技能，让 AI 对齐项目实际版本、按角色把关，不靠训练数据猜 API。文档库引擎：库维护者把内部库文档推上 docs-server 建全文索引，使用者的 AI 用一个技能检索所有库——内部库的真实用法，不再靠模型猜。

工程流程类技能需要显式输入命令调用；语言与框架规范在你编辑对应代码文件时自动生效。安装只要一条命令：

$ npx skills add cabinet-fe/prompt-engineering

下面分别说说它解决了什么问题、怎么选、怎么用。

三个核心优势

文档与代码实时对齐

代码改动如果影响了架构、规范或模块说明，当场直接更新对应文档，确保文档永远不说假话。没受影响的内容绝不乱碰，坚决不建冗余重复的摘要。

精准更新 · 拒绝冗余

识别实际版本，杜绝幻觉

语言和框架技能自动读取项目实际安装版本（如 package.json、go.mod、Cargo.lock），只使用对应版本的官方规范。

PART Ⅲ

文档库引擎 · docs-server

企业内部库文档检索系统：库维护者把文档推送到中心服务建全文索引，库使用者在编辑器里让 AI 经 Agent Skill 直接检索；服务端另带只读 Web UI，浏览器打开即可翻阅。一个技能覆盖所有库，无需逐库写技能、无需配 MCP。

库维护者                     中心服务                    库使用者
push-docs.mjs ──HTTP──▶ docs-server ◀──REST── docs-search 查询脚本
（零依赖 Node 脚本）     SQLite + FTS5 全文索引    （Agent 运行）
浏览器 ──直接访问──▶ 内置只读 Web UI

文档服务 docs-server/

Go 单进程 REST 服务：整库推送（单令牌 Bearer 鉴权）+ SQLite FTS5 全文检索（读路径免鉴权），内置只读 Web UI（库列表、目录树、Markdown 渲染、代码高亮、页内 TOC），编译为 CGO 关闭的单文件静态二进制，拷到服务器直接运行。

推送脚本 push-docs.mjs

零依赖单文件 Node 脚本（Node ≥ 24），复制到库仓库即可用：解析 frontmatter、本地校验、整库全量推送，手动或挂 CI 执行。

docs-gen 库维护者技能

按「文档读者是 AI」的标准生成与修订库文档；库代码改动后判定并同步受影响文档，再执行推送，让索引里的文档永远不说假话。

docs-search 库使用者技能

AI 运行内嵌零依赖查询脚本：列库、全文检索、按章节取文档。服务地址只读 DOCS_SERVER_URL，换库只换参数。

部署、配置、REST API 与内置 Web UI 说明，见 docs-server/README.md ↗。

三分钟上手

① 安装技能到 Agent

npx skills add cabinet-fe/prompt-engineering
npx skills add cabinet-fe/prompt-engineering --list
npx skills add cabinet-fe/prompt-engineering --skill setup --skill rush
npx skills add cabinet-fe/prompt-engineering -g

支持查看列表、按需挑选技能安装，或全局安装（-g）以在所有项目中生效。

② 两种常见使用方式

# 方式 A：分步执行（适合探索与精细把关）

explore 审批单想支持批量转办
to-spec approval-batch-transfer
to-tasks approval-batch-transfer
implement approval-batch-transfer P1
archive approval-batch-transfer

# 方式 B：rush 自动编排（任意环节可介入，大需求一键跑完）

rush 审批单想支持批量转办

③ 初始化后的项目目录结构

.agents/
├── docs/       项目概况 PROJECT；
│               代码类含架构/规范/地图/坏味道自查
├── scripts/    预检 precheck、任务管理 cooking
│               与规范模板
└── cooking/    临时开发记录（gitignore，不提交）
AGENTS.md       根索引文件，供 AI 按需加载具体文档

若执行过 acceptance 会额外生成 ACCEPTANCE.md 验收规范。任务完成后 cooking/ 临时记录会自动清除。

④ 文档库引擎：三步接入

# 维护者：推送库文档（脚本复制到自己仓库后执行）

node --env-file=.env scripts/push-docs.mjs

# 使用者：装检索技能，配服务地址

npx skills add cabinet-fe/prompt-engineering --skill docs-search
export DOCS_SERVER_URL=http://docs-server.internal:8080

服务端部署、二进制下载与配置说明见 docs-server/README.md。
