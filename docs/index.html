凭什么不一样

项目一直在变，过时文档会让 Agent 幻觉。这套技能包管的是已有文档，不另建一层摘要。

已有文档跟着代码走

改动把 CODE-MAP、技能、包内 AGENTS.md 说错了，当场改那一份。没说错就不动。sync-docs 可以单独点名，只改已有文档。

只改已有的 · 禁止另建一层

版本感知，不背旧 API

语言/框架技能先看已安装版本（lockfile、go.mod、rustc），再打开对应的 references/<版本>.md。训练数据里的过时写法？不存在的。

8 个技术栈 · 按版本分档

cooking 用完即删

进行中的功能写在 cooking/，完成后删掉。长期事实在代码和已有地图里。

不留验收复印件

处方 ✎

setup

一次性。访谈后分类，写 PROJECT.md、铺 .agents/docs/ 和脚本、覆写根 AGENTS.md。跑完 node .agents/scripts/precheck.mjs 应为 PASS。

一条链，从 setup 到归档

点每个节点看看它在干嘛、卡在哪。rush 只是编排器，不是另一套流程——产物、模板、并行规则跟单独调用完全一样。

🧱 setup

setup

每个目标仓库先跑一次。访谈后分类，写 PROJECT.md（代码类还有架构/规范/地图/坏味道）、复制脚本、覆写根 AGENTS.md。其它技能发现没 setup 会停下让你先跑，不代跑。

三分钟上手

① 装进你的 Agent

npx skills add cabinet-fe/prompt-engineering
npx skills add cabinet-fe/prompt-engineering --list
npx skills add cabinet-fe/prompt-engineering --skill setup --skill rush
npx skills add cabinet-fe/prompt-engineering -g

列技能、只装一部分、装到用户级（所有项目）。多数工程技能只在点名时跑。

② 挑一种姿势跑起来

# 分步走：需求含糊也不怕

explore 审批单想支持批量转办
to-spec approval-batch-transfer
to-tasks approval-batch-transfer
implement approval-batch-transfer P1
archive approval-batch-transfer

# 或者：一条命令跑完

rush 审批单想支持批量转办

③ 目标仓库会多出什么

.agents/
├── docs/       PROJECT；
│               代码类还有架构/规范/地图/坏味道
├── scripts/    precheck、spec-files
└── cooking/    进行中的功能（gitignore，别提交）
AGENTS.md       短索引，按需打开 docs，
                禁止一次加载全部

跑过 acceptance 还会多出 ACCEPTANCE.md 和可选的 acceptance/ 脚手架。cooking 完成后删掉。
